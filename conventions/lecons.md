# Leçons apprises : erreurs à ne pas répéter

Ce document consigne les erreurs réellement commises dans ce dépôt et la règle qui les évite. **Toute nouvelle erreur
ou surprise coûteuse y ajoute une ligne dans le commit qui la corrige** : on apprend de ses erreurs en les écrivant une
seule fois, ici. Format : constat, cause, règle.

## Suivi et livraison

| Constat | Règle |
|---|---|
| Le travail sur la migration Paie a été interrompu après des étapes partielles malgré la demande explicite de poursuivre. | Appliquer la boucle Ralph de `conventions/workflow.md` : enchaîner les étapes autorisées jusqu'au résultat prouvé ou à un blocage concret nécessitant une décision. |
| Le suivi dans des fichiers markdown (plan de 600 lignes, handoff, tableaux d'état) divergeait du code et se contredisait d'une reprise à l'autre. | Le suivi d'une tâche vit dans Jira (projet `KAN`) et l'état technique dans le code et les tests. Aucun fichier markdown ne suit l'avancement ; une décision durable va dans la convention ou le document de conception concerné. |
| Une branche partait de la mauvaise base, des commits restaient locaux, la PR n'était pas à jour. | Avant tout `git` ou `gh` : vérifier le dossier courant, la branche et `git status`. Une seule branche de travail et une PR à la fois ; après fusion, ne garder que `main`. |
| Une CI verte sur un ancien commit a été prise pour une validation. | Les 4 contrôles requis (`backend`, `frontend`, `full-stack`, `ia`) doivent être verts sur le **dernier commit poussé**. |
| Un refus automatique d'une commande a été contourné par une autre voie. | Un refus n'est jamais contourné : donner la commande au propriétaire, ou lui demander d'ajouter la règle de permission. |
| Un ticket de mesure (KAN-9, démarrage du service `ia`) a été clos après la seule mesure de l'import, sans mesurer le démarrage complet du conteneur. | Avant de clore, comparer ce qui a été mesuré à ce que le titre promet ; ce qui ne l'est pas est mesuré ou écrit « non vérifié », et le ticket reste ouvert tant qu'il manque. |
| Plusieurs tâches avançaient en parallèle pendant l'attente de la CI. | Une tâche va jusqu'à « Terminé(e) » (fusion, branche supprimée, preuve) avant d'ouvrir la suivante ; pendant l'attente, lecture et mesures sans branche seulement. |
| Une tâche était annoncée « faite » sans preuve. | Une tâche passe à « Terminé(e) » en Jira seulement avec sa preuve en commentaire (test, trace, capture, lien de PR). Ce qui n'a pas été vérifié est écrit « non vérifié ». |
| Le serveur MCP a été écrit sur le SDK `mcp` alors que FastMCP 4, la couche au-dessus, existait : seule la version du paquet en main avait été vérifiée. | Avant tout choix de dépendance, chercher la dernière stable du paquet **et** de sa couche supérieure ou de ses alternatives officielles (PyPI, dépôt, documentation) ; règle « Toujours la dernière version stable » d'`AGENTS.md`. |

## Outils et scripts

| Constat | Règle |
|---|---|
| Un heredoc Bash a altéré des antislashs et des guillemets dans un fichier. | Écrire les fichiers avec les outils `Write` et `Edit`, jamais avec un heredoc ou `echo`. |
| Les fins de ligne CRLF ont fait échouer silencieusement un remplacement sur plusieurs lignes. | Vérifier le résultat d'un remplacement multi-lignes ; normaliser les fins de ligne avant de remplacer par script. |
| Un fichier a été écrasé par erreur. | Le restaurer avec `git checkout -- <fichier>` puis le réécrire ; lire un fichier avant de l'écraser. |
| `transitionJiraIssue` a échoué avec `transition` au lieu de `transitionId`, puis avec un identifiant qui n'était pas valable pour le ticket (10005 refusé sur une tâche en « Revue en cours » ; 41 accepté). | Passer `transitionId` ; ne jamais fixer un numéro de mémoire : les transitions valides dépendent du statut courant du ticket. Lire `allowedValues` dans l'erreur et en reprendre l'identifiant. |
| Une recherche récursive sur tout le dépôt a dépassé le délai. | Utiliser l'outil `Grep`/`Glob` avec un dossier ou un motif ciblés, ou lancer la commande longue en arrière-plan. |

## Tests et qualité

| Constat | Règle |
|---|---|
| Les premières routes Paie Python acceptaient `AAAAMM` et renvoyaient des identifiants plats alors que le frontend envoyait `AAAA-MM` et attendait des résumés de références ; les options rejetaient même son tri. | Avant de déclarer un domaine migré, comparer chaque requête et réponse au service Angular et au contrôleur Spring, puis exécuter au moins un test HTTP de contrat sur la base de test. |
| Deux E2E du wizard Paie utilisaient encore une réponse d'analyse simulée sans le nouveau champ obligatoire `avertissements` ; le store levait une erreur avant d'afficher le contrôle. | Quand un contrat de réponse évolue, mettre à jour toutes les réponses simulées consommées par les E2E, puis exécuter les scénarios Playwright concernés. |
| Une mesure de débordement horizontal dans les e2e lisait la page avant le rendu du contenu. | Attendre un élément rendu (titre, ligne de tableau) avant de mesurer ou d'ouvrir une palette de commandes (`Ctrl+K`). |
| Le premier lancement de `ng serve` rendait des e2e instables. | Attendre le titre de la page avant d'interagir ; relancer avec `--workers=1` avant de soupçonner une régression. |
| Des vulnérabilités critiques transitives (npm) bloquaient la CI. | Les corriger par `overrides` dans `package.json` (par exemple `dompurify`), pas en retirant le contrôle. |
| Un défaut d'une bibliothèque tierce (A2UI avec zod 4) a été contourné sans être signalé. | Contourner par un repli lisible côté ERP **et** ouvrir un signalement chez l'éditeur (texte anglais, reproduction minimale) ; consigner son lien dans la tâche Jira. |
| Le comportement d'un framework a été affirmé de mémoire. | Lire la page officielle ou le code source en entier avant d'affirmer ; sinon écrire « non vérifié » (règle d'`AGENTS.md`). |
| Un tableau a été livré avec un tri qui ne changeait que la page affichée, des vues sans recherche et sans export. | Tri, recherche et export PDF (mêmes filtres et tri que l'écran) sont exigés dans tout tableau et tout domaine, y compris pendant une migration : voir `conventions/frontend.md`, section « Tri, recherche et export ». |
| Des tests unitaires ont été réécrits pour passer au lieu de corriger la cause. | Corriger la cause ; ne pas affaiblir une assertion métier. |
| Une borne de contexte (7 outils par compétence) a été présentée comme une limite de capacité, ce qui a fait craindre des scénarios sans outil. | Écrire dans la règle ce que le nombre borne (schémas par domaine) et ce qu'il ne borne pas (le total d'un tour, les domaines atteignables par le repli) ; un test de couverture prouve que chaque scénario garde ses outils. |
| Un test d'API lançait le vrai modèle d'embeddings de routage. | Injecter le routage dans `creer_app` pour les tests d'API ; un seul test charge le vrai modèle (MiniLM, préchargé dans l'image Docker, jamais téléchargé au démarrage). |
| Le prompt seul n'a pas suffi contre l'injection : deux cas (consigne dans le prompt système, consigne dans le texte cité) échouaient encore une fois sur trois. | Une règle de prompt demande au modèle de se retenir, elle ne l'y oblige pas. Toute protection contre une fuite (prompt, noms d'outils, valeur interdite) est doublée d'un contrôle déterministe de la réponse avant envoi ; le prompt ne sert qu'à réduire la fréquence. |
| L'agent a inventé le libellé d'une fonction que l'outil ne renvoyait pas. | La description de chaque outil dit ce que la réponse contient et ce qu'elle ne contient pas, et que l'agent s'abstient quand un champ manque. Le critère `fondement` du banc vérifie les libellés comme les chiffres. |
| Un mois de paie non importé a été présenté comme une masse de 0 MAD. | Un outil dont l'absence de donnée se confond avec zéro l'écrit dans sa description et indique l'outil de vérification (ici `paie_periodes`). |
| Un cas homonyme a été résolu en prenant le premier résultat. | Plusieurs correspondances : l'agent demande une précision, il ne choisit pas au hasard (règle de prompt, cas du jeu). |
| Les défauts d'un domaine ne sont apparus qu'avec 60 cas × 3 essais et la lecture des traces. | Tout nouveau domaine suit la procédure de `conventions/agents-ia.md`, section « Intégrer un nouveau domaine à l'agent » : cas ajoutés au jeu avant la livraison, traces lues, descriptions d'outils corrigées à partir des traces. |
| Un juge LLM et un rejoueur d'évaluation ont été écrits à la main alors que `openevals`, déclaré en dépendance, les fournit. | Avant d'écrire, chercher la ligne du cas d'usage dans le registre de [`ingenierie-agentique.md`](ingenierie-agentique.md) ; une dépendance déclarée et jamais utilisée est utilisée ou retirée. |
| Une même normalisation d'accents a été écrite dans deux modules. | Une règle ne vit que dans une couche : chercher l'existant avant de coder ; un seul exemplaire, testé une fois. |
| Une ligne trop longue et un test frontend instable n'ont été vus qu'en CI (trois exécutions perdues, publication des images sautée). | Contrôles locaux avant la PR ; un test instable est corrigé à sa cause ou mis en quarantaine par ticket, jamais relancé jusqu'à ce qu'il passe. |
| A2UI a été envisagé comme remplaçant d'AG-UI. | Ce sont deux couches : A2UI décrit l'interface, AG-UI connecte agent et application (événements, état, outils côté client, interruptions) et traduit les messages A2UI. Aucun ne remplace l'autre. |
| Une liste de mois (`findDistinctPeriodeBy…`) répondait 500 en production : Spring Data lisait le nom comme une requête d'entités ; les tests de service moquaient le dépôt et ne le voyaient pas. | Une méthode de dépôt qui renvoie autre chose que l'entité s'écrit avec `@Query` explicite et se teste une fois sur une vraie base (`AuditIntegrationTestBase`). |
| Un test d'intégration a laissé des lignes dans la base partagée et fait échouer en CI un autre test qui vide `paie`. | Tout test sur la base partagée supprime en `@AfterEach` ce qu'il a créé (hors des tables d'audit) ; vérifier en lançant le test avec ses voisins, pas seul. |
| Monter une sous-application ASGI (serveur MCP) à la racine de FastAPI a transformé les 405 des routes REST en 404 : le montage capte tous les chemins. | Ajouter une sous-application comme une `Route` sur son seul chemin, pas par `mount("/")` ; la suite de tests des routes existantes le détecte, la lancer en entier après tout montage. |
| Le client envoyait la période multipart alors que FastAPI la déclarait en query string, et les corrections n'étaient pas liées au classeur analysé. | Pour un wizard multipart, déclarer explicitement fichier, période et données de correction en champs `File`/`Form`, puis recalculer côté serveur les propositions depuis le même fichier avant toute écriture. Vérifier les trois requêtes par test HTTP et contrat Angular. Source : [FastAPI — Request Forms and Files](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/). |

## Documentation

| Constat | Règle |
|---|---|
| Des nombres écrits en dur dans la documentation (versions, nombre d'outils MCP, seuils) devenaient faux. | Les faits vérifiables sont dans `scripts/ia/verrous.txt` ; `scripts/ia/check-docs-code.mjs` les compare au code en CI. Un nouveau fait de ce type y est ajouté. |
| Des fichiers supprimés ont perdu des informations utiles. | Avant de supprimer un document, vérifier que chacune de ses informations durables figure ailleurs ; indiquer le commit qui le conserve (`git show <commit>:<chemin>`). |
| La documentation de la migration FastAPI était dans `docs/migration-fastapi/`, un dossier parallèle au site de documentation. | Toute documentation de migration (stratégie, inventaire, parité par domaine) vit dans `site/docs/migration/` (Docusaurus, `npm run build` sans lien cassé), jamais dans `docs/` ; l'inventaire est généré à cet endroit par `scripts/migration/inventaire-backend.py`. |
| Le banc d'évaluation réel contournait le routage (aucune compétence épinglée) : il mesurait le seul repli, +1 tour de modèle presque partout. | Tout banc doit construire l'état d'entrée comme le service (`pinned_skills` calculé par `Routeur`) ; vérifier qu'un changement de chemin d'exécution est bien celui que mesure le banc. |
| Un cas ajouté au banc Python utilisait un marqueur absent des données du banc Java, ce qui cassait le jeu partagé. | Pour tout nouveau marqueur, adapter chaque fournisseur de données du banc et lancer le contrôle de cohérence avant le banc réel. |
| Une URL PostgreSQL construite par interpolation échouait avec un caractère réservé dans le mot de passe. | Construire un objet `URL.create` SQLAlchemy avec les champs séparés et le transmettre au moteur ; tester des secrets contenant `@`, `/`, `:` et `%`. Source : https://docs.sqlalchemy.org/en/21/core/engines.html#creating-urls-programmatically. |
| Le banc déclarait inventées les secondes d'un horodatage ISO parce que la source contenait aussi des fractions de seconde. | Analyser les horodatages JSON avec `datetime.fromisoformat` et tester séparément une décimale métier qui ne doit pas être assimilée à une heure : https://docs.python.org/3/library/datetime.html#datetime.datetime.fromisoformat. |
| Deux exports `pg_dump` de données inchangées avaient des empreintes différentes à cause de leur clé `\restrict` aléatoire. | Pour comparer des dumps en lecture seule, fixer `--restrict-key` avec une valeur de test puis calculer l'empreinte ; ne jamais fixer cette clé pour une sauvegarde destinée à être restaurée. Source : https://www.postgresql.org/docs/18/app-pgdump.html. |
| Au premier démarrage PostgreSQL, `pg_isready` par socket a déclaré le service sain pendant le serveur temporaire d'`initdb`, juste avant son arrêt ; `phoenix-db-init` a reçu `connection refused` en TCP. | Le healthcheck Compose de PostgreSQL teste explicitement `-h 127.0.0.1` : il ne passe qu'après le démarrage TCP du serveur final. |
| Importer le module IA à l'import de l'API chargeait le `.env` local par effet de bord d'une dépendance IA et modifiait des paramètres de configuration API. | Charger les modules IA uniquement à l'activation explicite dans la fabrique de l'application API ; vérifier qu'un simple import ne modifie pas l'environnement. |
| L'image API a copié le venv `uv` construit sous `/app/api/.venv` vers `/app/.venv` : les scripts gardaient le shebang du chemin initial et ne démarraient plus. | Garder le même chemin absolu du venv entre les étapes de build et d'exécution, puis exécuter réellement l'`ENTRYPOINT` dans l'image avant de déclarer sa construction prouvée. |
| Sur une base LiteLLM neuve, les 224 migrations Prisma ont pris près de quatre minutes ; le healthcheck de l'image a épuisé sa période de démarrage de 90 secondes et Compose a déclaré le service malsain juste avant qu'il soit prêt. | Dimensionner `HEALTHCHECK --start-period` sur un premier démarrage réellement mesuré, avec marge ; retester le parcours Compose sur volume neuf. |
| Un critère « l'outil exact attendu doit être appelé » faisait échouer des réponses justes par un autre chemin et bridait l'agent. | Le jeu juge le résultat (valeurs, fondement, sécurité, juge) ; la trajectoire est rapportée seulement. Un banc d'un seul passage de 24 cas cachait l'instabilité et les failles (injection, noms d'outils, premier homonyme pris au hasard) : 60 cas jouées 3 fois les ont révélées. |
| Le test de rendu WeasyPrint a été lancé sur Windows sans la bibliothèque native Pango, puis a échoué avant de tester le PDF. | Garder les tests de calcul et de HTML exécutables localement ; effectuer la vérification du rendu PDF dans l'image Linux qui embarque les bibliothèques natives, et rapporter séparément ces deux preuves. |
| La sélection existante des équipes à détailler a d'abord été interprétée comme une demande de fusionner ces équipes dans le rapport. | Conserver la sélection et le regroupement comme deux choix distincts ; une fusion n'a lieu que lorsque l'utilisateur la demande explicitement dans l'export. |
| Le prototype Excel comparait les codes d'équipe aux libellés envoyés par l'assistant et comparait une feuille équipe à tout le mois précédent. | Résoudre les libellés à la frontière du contrat, puis appliquer exactement le même périmètre au mois précédent ; vérifier par un classeur qui contient plusieurs équipes. Source métier : `site/docs/domaines/rapport/index.md` et `PaiePerimetreService`. |
| L'option d'import « Ignorer et conserver 0 » ignorait tous les avertissements, y compris un changement de salaire qui doit passer par le wizard. | Associer chaque confirmation à son avertissement précis ; un accord sur un salaire nul ne vaut jamais accord pour modifier le salaire d'un employé. Source métier : décision du propriétaire consignée dans `site/docs/migration/paie.md`. |
| Le lecteur Python comptait les lignes Excel entièrement vides après l'en-tête, alors que le lecteur Spring les ignorait ; l'import pouvait ensuite lire un CIN absent. | Partager une lecture des seules lignes utiles entre analyse et import, avec numéro de ligne d'origine, et tester un trou entre deux employés. Source métier : `LecteurFichierPaie` et `site/docs/domaines/rapport/index.md`. |
| L'analyse Python ne signalait ni bulletin déjà présent, ni CIN en doublon, ni champs obligatoires absents ; l'import échouait plus tard ou tentait un écrasement. | Vérifier ces conflits pendant l'analyse, avant toute écriture, puis conserver le refus dans la transaction d'import. Source métier : `PaieImportService.erreurDuFichier` et décision du propriétaire dans `site/docs/migration/paie.md`. |
| L'analyse utilisait `elif` pour le salaire nul puis le salaire différent : un fichier à 0 sur une fiche à 1 000 ne montrait que le premier avertissement, et « Ignorer 0 » aurait contourné le wizard. | Émettre les deux avertissements avec des codes métier distincts et limiter chaque confirmation à son code ; tester explicitement le cumul sur la même ligne. Source métier : décision du propriétaire dans `site/docs/domaines/paie/contrats.md`. |
| L'import Paie mettait à jour l'employé, mais l'historique d'audit déclarait `date_naissance` et `date_embauche` en `String` malgré leurs colonnes PostgreSQL `DATE` ; l'insertion de révision échouait et annulait tout l'import. | Déclarer dans la table d'audit SQLAlchemy le type réel de chaque colonne et éprouver une modification d'employé dans une transaction PostgreSQL avec les écouteurs d'audit installés. Source : https://docs.sqlalchemy.org/en/21/core/type_basics.html#sqlalchemy.types.Date. |

| Un `ValueError` levé par le service Paie sortait en HTTP 500 alors que Spring renvoie 400 ou 404. | Lever une `ErreurMetier` dédiée (statut explicite) pour tout refus métier ; un test d'API vérifie le code et le message. |
| J'ai affirmé que Spring écrit une entrée de journal distincte pour la synchronisation d'équipe ; l'aspect n'écrit que l'action la plus externe. | Lire `GenericAuditAspect` avant d'affirmer un comportement d'audit et ajouter un test qui compte les entrées du journal. |
| Un test Angular ciblé échouait (`jsdom` introuvable) : `ng test` seul n'utilise pas le navigateur du projet. | Lancer `ng test --watch=false --browsers=ChromiumHeadless --include=...` (script `npm test`). |
| Pydantic sérialise `Decimal` en chaîne JSON (`"600.00"`) alors que Jackson écrit un nombre ; les écrans Angular typés `number` recevaient des chaînes. | Annoter tout montant ou mesure de réponse avec `Nombre` (`PlainSerializer(float, when_used="json")`, Decimal conservé en Python) ; comparer la forme JSON des réponses, pas seulement les valeurs. Source : https://docs.pydantic.dev/latest/api/standard_library_types/ (Decimals, Serialization). |
| Un contrôle de style a remplacé les signes × et − dans des textes de définition renvoyés par l'API, ce qui changeait le contrat de Spring. | Les chaînes d'un contrat HTTP se conservent à l'identique, avec `# noqa: RUF001` ; comparer le texte, pas seulement la structure. |
| Un commit de route basé sur un ancêtre commun a retiré silencieusement `DELETE /employees/{id}` lors de son intégration. | Après toute intégration de changements de route, vérifier le diff final contre les matrices RBAC/audit et comparer les routes OpenAPI, pas seulement les fichiers modifiés par le commit. |

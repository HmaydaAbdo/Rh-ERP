# Conformité des métriques — 2026-10-12

## Périmètre et configuration

Le backend utilise Micrometer avec le registre Prometheus (`micrometer-registry-prometheus`).
`application.yml` n'expose que `/actuator/health` et `/actuator/prometheus`, et ajoute le tag
commun `application=paie`. La sécurité applicative autorise ces deux endpoints sans jeton ; le
réseau de production les limite au serveur : le port backend est lié à `127.0.0.1` et nginx inner
ne relaie que `/actuator/health` (`docs/architecture.md`). Aucun collecteur Prometheus, stockage de
séries temporelles, tableau de bord ou moteur d'alertes n'est déployé ni configuré dans le dépôt.
Le branchement opérationnel reste suivi dans `TODO.md`.

Spring Boot/Micrometer fournit aussi les mesures techniques disponibles selon les dépendances et
le contexte d'exécution (HTTP, JVM, processus et pool JDBC). Le nom de l'application est leur
dimension commune. Les routes HTTP sont instrumentées par leurs motifs configurés, jamais par les
valeurs concrètes d'identifiants de chemin ; aucune identité, donnée métier, requête, secret ou
horodatage n'est ajouté comme tag applicatif.

Le `ThreadPoolTaskExecutor` SMTP nommé `mailTaskExecutor` est aussi instrumenté par Spring Boot avec
les mesures d'exécuteur (activité, file et taille du pool), identifiées par le nom fixe du bean.
`AsyncConfigTest` vérifie le rejet immédiat après saturation des 4 travailleurs et de la file de 100
tâches ; cela ne mesure pas la disponibilité réelle du serveur SMTP.

## Métriques applicatives

| Nom Micrometer | Type / unité | Dimensions | Signal et interprétation |
|---|---|---|---|
| `rh.audit.ecriture.echec` | compteur d'événements | `categorie` : `OPERATION`, `SECURITE`, `ACCES` | Écriture d'une entrée d'audit impossible. Une hausse signale une trace manquante ; consulter les journaux et rétablir le stockage d'audit. |
| `rh.audit.evenement.securite` | compteur d'événements | `action` : valeurs de `ActionSecurite` | Volume des événements de sécurité effectivement journalisés. Ne remplace pas le journal d'audit. |
| `rh.audit.integrite.compromise` | jauge, 0 ou 1 | aucune | Vaut 1 si le compte applicatif peut modifier les tables d'audit ; vérifier les rôles et privilèges PostgreSQL. |
| `rh.audit.chaine.invalide` | jauge, 0 ou 1 | aucune | Vaut 1 si le contrôle local du chaînage détecte une altération ; préserver les preuves et lancer la procédure d'incident d'audit. |
| `rh.chantier.sync.success` | compteur de synchronisations | aucune | Synchronisations de chantiers terminées avec succès. |
| `rh.chantier.sync.failure` | compteur de synchronisations | aucune | Synchronisations échouées ; vérifier le service ERP distant et le prochain cycle planifié. |
| `rh.chantier.sync.records.ignored` | compteur de lignes | aucune | Lignes ignorées pour code manquant ou conflit d'intégrité ; rapprocher les données source. |
| `rh.chantier.sync.duration` | timer, secondes à l'export Prometheus | aucune | Durée de chaque synchronisation réussie ou échouée ; Micrometer convertit les millisecondes reçues par le code vers l'unité de base du registre. |

Les tags d'audit sont désormais typés par `CategorieAudit` et `ActionSecurite` : leurs ensembles
de valeurs sont fermés. Les métriques de synchronisation ne portent aucun tag. Les tests
`MetricsConformityTest` verrouillent types, valeurs, durées et dimensions ; `AuditDefaillanceTest`
et `AuditIntegriteTest` vérifient les compteurs et jauges au cours de scénarios d'intégration.

## Tableau de bord et règles à raccorder

Le tableau de bord d'exploitation à créer dans le collecteur doit présenter :

1. disponibilité HTTP, débit et latence par route normalisée et statut ;
2. compteurs d'échec d'écriture d'audit et état des deux jauges d'intégrité ;
3. succès, échecs, lignes ignorées et quantiles de durée de synchronisation.

Règles proposées pour le raccordement :

| Signal | Condition proposée | Durée | Responsable | Action attendue |
|---|---|---|---|---|
| Intégrité ou chaîne d'audit compromise | jauge `> 0` | 1 minute | opérateur applicatif de garde | préserver les journaux, vérifier les privilèges/la chaîne et déclencher la procédure d'incident d'audit. |
| Écriture d'audit en échec | augmentation du compteur `> 0` | fenêtre de 5 minutes | opérateur applicatif de garde | vérifier PostgreSQL et le stockage d'audit ; confirmer la traçabilité avant de reprendre les opérations concernées. |
| Synchronisation de chantier en échec | augmentation du compteur `> 0` | fenêtre de 15 minutes | opérateur applicatif de garde | vérifier l'ERP distant et le cycle suivant ; appliquer la procédure documentée de synchronisation si l'erreur persiste. |

Ces seuils sont des valeurs de départ pour le collecteur et doivent être confirmés avec
l'exploitation à la mise en service. La portée de collecte doit rester privée ; les alertes
doivent être routées vers le responsable désigné et testées avant production. Aucun stockage,
tableau de bord ou acheminement d'alerte en production n'est prétendu par ce contrôle local.

# Contrôle sécurité — 2026-10-12

## Résultat local

Le périmètre de sécurité vérifiable dans le dépôt est **conforme localement** à
[`conventions/security.md`](../../conventions/security.md). Les vérifications portent sur le code
backend, ses permissions, la chaîne JWT, la configuration CORS/CSRF et les sessions. Les valeurs et
les tests utilisent uniquement des identifiants synthétiques ; aucune configuration ni donnée de
production n'a été consultée.

| Contrôle | Preuve exécutée | Résultat |
|---|---|---|
| Permissions par endpoint | `EndpointSecurityTest` | Tous les endpoints métier découverts ont une permission explicite, refusent une identité sans cette permission et acceptent celle qui la possède ; la table de référence des permissions correspond aux annotations. |
| Chaîne JWT réelle | `JwtSecurityChainTest` | Signature HS256, mauvais secret, émetteur erroné, destinataire erroné, expiration absente, identité sans permission, permission effective et origine de refresh cookie contrôlés par MockMvc. |
| Secret JWT | `JwtSigningKeyTest` | Base64 invalide et clé de moins de 256 bits rejetées ; clé de 256 bits acceptée. `JwtService` et `SecurityConfig` utilisent la même validation avant signature/vérification. |
| CORS et CSRF | `SecurityConfigCorsTest`, `JwtSecurityChainTest` | Liste CORS explicite validée ; pré-vol autorisé/refusé ; `/auth/refresh` refuse une origine tierce ou absente. `/auth/logout` requiert en plus un Bearer valide. |
| Connexion, sessions et récupération | `AuthServiceTest` (23 tests) | Réponses génériques, verrouillage, rotation à usage unique, détection de réutilisation, expiration, désactivation, révocation, demande de récupération non énumérable et réinitialisation couverts. |
| Verrouillage persistant | `VerrouillageConnexionIntegrationTest` sur Testcontainers | PostgreSQL 18.6, Flyway V1→V21 ; cinq échecs persistés déclenchent un blocage de quinze minutes, y compris pour le bon mot de passe pendant le blocage, et l'événement de sécurité est conservé. |
| Politique des mots de passe et CORS | `PolitiqueMotDePasseTest` (3), `SecurityConfigCorsTest` (4) | Règle de mot de passe et validations d'origine couvertes. |
| Suite sécurité ciblée | Maven, Java 21 | **55 tests réussis**, 0 échec, 0 erreur ; compilation principale et tests réussie. PostgreSQL et les identifiants utilisés étaient jetables/synthétiques. |

Les jetons émis contiennent `iss` et `aud`, tous deux égaux à `spring.application.name` (`paie`). Le
décodeur ne permet que HS256 et valide l'émetteur, le destinataire, l'expiration, l'émission et les
claims `sub`/`uid` requis. Les origines autorisées restent celles fournies par `CORS_ALLOWED_ORIGINS`.
Les opérations métier restent autorisées côté serveur par permission ; les guards frontend ne sont
qu'une aide d'interface.

## Vérifications réservées à l'hôte de production

Elles sont isolées dans la rubrique **Travail côté serveur** de [`TODO.md`](../../TODO.md) :

- configurer le secret JWT aléatoire propre à la production et les credentials de démarrage dans le
  stockage protégé de l'hôte ; vérifier `COOKIE_SECURE=true` derrière HTTPS ;
- renseigner les seules origines HTTPS de production et confirmer que Swagger reste désactivé ;
- après la migration qui applique V21, contrôler le verrouillage et la révocation sur le service réel ;
- confirmer que nginx outer transmet la bonne IP à nginx inner et que les limites d'essais s'appliquent
  par adresse réelle. La configuration de nginx outer attend toujours l'exemple du propriétaire.

Aucune action sur le serveur, aucun test avec des comptes ou des secrets réels, et aucune vérification
de CI n'ont été effectués dans ce contrôle.

Les sources frontend n'ont pas été modifiées. Les tests Angular navigateur n'ont pas été relancés
dans ce contrôle : aucun navigateur Chromium exploitable n'était disponible dans l'environnement local.

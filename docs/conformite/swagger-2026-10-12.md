# Contrôle de conformité — Swagger/OpenAPI — 2026-10-12

## Résultat local : conforme

Le contrat est généré depuis les routes et DTO du backend avec Springdoc ; il n'existe pas de
spécification manuelle concurrente. Le contrôle s'appuie sur le document réellement produit par
`GET /v3/api-docs` dans `OpenApiContractTest`, et non uniquement sur les annotations du code.

| Exigence | Vérification et preuve |
|---|---|
| Organisation et identité des opérations | `ArchitectureConventionsTest` contrôle un `@Tag` par contrôleur et un `@Operation` par route. Les tags de même nom ont une description harmonisée. `OpenApiContractTest` vérifie les noms de tags uniques, chaque opération générée, ses `operationId` uniques, son résumé et des réponses décrites. |
| Sécurité décrite | `OpenApiConfig` expose le schéma Bearer JWT pour les routes protégées. Les routes publiques d'authentification annulent explicitement cette exigence ; `/auth/refresh` documente en plus le refus d'une origine absente ou non autorisée. Le contrat teste ces exceptions et les réponses 401/403 des routes protégées. |
| Corps d'erreur et statuts significatifs | Les réponses métier 400/404/409 utilisent le schéma `ErrorResponseDto`. Le contrat complète les erreurs de validation (400), les absences de ressource par identifiant (404), les refus d'authentification/permission (401/403) et les erreurs serveur (500). Les imports documentent les deux corps réellement renvoyés en 400 : résultat détaillant les lignes ignorées ou `ErrorResponseDto` pour un fichier illisible. |
| Imports et téléchargements | Les trois imports déclarent `multipart/form-data`, le champ binaire `file`, le format XLSX et la limite de 20 Mo appliquée par `application.yml`. Les trois modèles, l'export Excel et le rapport PDF déclarent leurs types MIME et leurs réponses binaires. |
| Intégrité du document généré | `OpenApiContractTest` passe le document à Swagger Parser 2.1.48 (support OpenAPI 3.1) et exige zéro diagnostic. Il vérifie aussi version, chemins, opérations, unicité des tags et identifiants, descriptions, schémas d'erreur et de fichier, et résolution de toutes les références locales `$ref`. |
| Exposition | `application.yml` éteint Swagger et OpenAPI par défaut. `DocumentationApiSecurityTest` vérifie la protection lorsqu'ils sont éteints ; `DocumentationApiAllumeeSecurityTest` vérifie leur disponibilité explicite en développement sans rendre l'API métier publique. |
| CI | Le workflow `.github/workflows/ci.yml` exécute `./mvnw -B test` ; le nouveau test d'intégration fait donc partie de la porte backend. La CI n'a pas été consultée ni exécutée pendant ce contrôle. Aucun contrat OpenAPI n'étant publié à comparer, le contrôle de breaking changes n'est pas applicable à ce dépôt aujourd'hui. |

## Vérifications locales exécutées

La commande ciblée a été exécutée avec Java 21, Testcontainers et PostgreSQL 18 + pgvector :

```powershell
cd backend
.\mvnw.cmd -B -ntp '-Dtest=OpenApiContractTest,ArchitectureConventionsTest,DocumentationApiSecurityTest,DocumentationApiAllumeeSecurityTest' test
```

Résultat : **18 tests, 0 échec, 0 erreur — BUILD SUCCESS**. Le test de contrat démarre la vraie
application sur une base PostgreSQL de test et lit sa spécification Springdoc générée. Le contrôle
n'inclut pas une exécution CI ni une vérification de configuration sur l'hôte de production ; la
désactivation par défaut et les contrôles applicatifs sont couverts localement.

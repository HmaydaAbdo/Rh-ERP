# Contrôle de conformité — audit — 2026-10-12

## Conclusion locale

Le périmètre technique vérifiable dans le dépôt est **conforme localement** à
[`conventions/audit.md`](../../conventions/audit.md). Les tests backend utilisent des identités et des données
synthétiques sur PostgreSQL jetable ; aucune donnée ni configuration de production n'a été consultée.

| Exigence | Mise en œuvre et preuve |
|---|---|
| Catalogue et couverture des écritures | `docs/audit/README.md` documente les actions, catégories et périmètres. `AuditArchitectureTest` vérifie les entités auditées ou explicitement exclues, les services d'écriture annotés ou justifiés, les types d'action, les périmètres et l'absence d'écritures de masse. |
| Acteur, contexte et corrélation | Les révisions et entrées portent l'acteur figé, l'origine, l'heure et le `request_id`; `AuditRevisionTest`, `AuditSynchronisationTest` et `AuditSecurityEventsTest` contrôlent les requêtes, tâches, migrations, démarrage et contexte inconnu. |
| Succès, refus et erreurs | `AuditOperationTest`, `AuditImportTest`, `AuditAccesTest` et `AuditSecurityEventsTest` couvrent opérations, imports, exports, événements de sécurité, refus et résultats échoués. |
| Atomicité et indisponibilité | `AuditDefaillanceTest` vérifie que l'écriture métier est annulée si sa trace obligatoire échoue, que l'échec est conservé séparément quand possible et qu'une panne de trace de sécurité est comptée sans bloquer la connexion. |
| Intégrité et absence de suppression silencieuse | `AuditIntegriteTest` vérifie le compte applicatif restreint et l'interdiction de modifier/supprimer les tables d'audit. Il contrôle aussi que la chaîne SHA-256 détecte une modification directe et redevient valide après annulation de cette altération de test. |
| Accès et exposition | `docs/rbac/audit.md` réserve la lecture à `AUDIT_READ`; `AuditConsultationTest` valide les endpoints de lecture, la pagination et l'absence de route API d'altération. Les secrets ne sont pas enregistrés dans les tests d'événements (`AuditSecurityEventsTest`). |
| Conservation déclarée | `docs/audit/README.md` consigne la décision RH de conservation à vie sans purge pour `OPERATION`, `SECURITE`, `ACCES` et Envers, ainsi que la décision du 2026-10-15 de conserver les CSV pgAudit pendant 90 jours. Ce contrôle vérifie la présence de ces règles documentées, sans évaluer leur validité juridique. |
| Suite backend | `mvn -B -ntp -Dtest=Audit*Test test`, Java 21, PostgreSQL 18.6 Testcontainers, Flyway V1→V21 : **73 tests réussis, 0 échec, 0 erreur**. Variables d'identité et d'application synthétiques alignées sur la configuration de test du dépôt. |

Les cinq specs Angular du module Audit ont été découvertes, mais le lancement local du runner reste figé sur `Building...` même après installation de Chromium ; elles ne sont donc pas comptées comme exécutées dans cette preuve. Aucun fichier frontend n'a été modifié. Le contrôle des permissions de consultation porte sur l'autorisation backend, vérifiée par `AuditConsultationTest`.

La construction locale antérieure de l'image PostgreSQL avec pgAudit et son test `AUDIT: SESSION` sont décrits dans [`docs/audit/README.md`](../audit/README.md) et ne remplacent pas les contrôles serveur. Aucune vérification CI n'a été faite dans ce contrôle.
